# Зафиксированные решения

- Telegram Mini App; клиентская часть и админка — в одном интерфейсе.
- Frontend: React, TypeScript, CSS, Vite.
- Backend: C#, ASP.NET Core, .NET 10 LTS; Telegram.Bot для общения с Telegram.
- PostgreSQL с первого этапа; EF Core и Npgsql для работы с базой.
- Один репозиторий, отдельные проекты фронтенда и сервера.
- Backend разделён на Domain, Application, Infrastructure, Api и Contracts; запускается одно ASP.NET Core приложение.
- Внутри слоёв код организуется по фичам; HTTP-интерфейс — Minimal API. Contracts хранит публичные DTO и не зависит от Domain/EF/Telegram.
- На этапе MVP совместная публикация: сервер отдаёт собранный фронтенд и API.
- Изображения — локальные файлы проекта или заглушки.
- Утверждён светлый дизайн: чёрные кнопки, акценты #D8FF2A, нейтральная
  зернистая фактура с разнообразными формами на всех экранах. Отсутствующее
  фото обозначается как иллюстрация; реальные фото имеют приоритет.
- Роли клиента и администратора; проверка прав выполняется сервером.
- Одна карточка товара с выбором объёма, размера или оттенка внутри неё.
- У товара один бренд и один тип косметики.
- Цена задаётся для конкретного варианта товара; валюта — рубли.
- Учёт и показ остатков исключены из текущего MVP.

Архитектура: [architecture.md](architecture.md). Работа по ролям:
[workflow.md](workflow.md). Разбиение, анализ и результаты шести фич:
[features.md](features.md).

## Объём MVP

Клиент: каталог, фильтры по бренду и типу, цена в каталоге, подробная
карточка товара с выбором варианта. Администратор: создание и редактирование
товаров и их вариантов, цены, скрытие и восстановление товаров, справочники.

Оплата, заказы, учёт остатков, отзывы и средняя оценка — следующие этапы.
Количество, отметки о наличии и история изменения остатков сейчас не реализуются.

Минимальная модель данных согласована и описана в [data-model.md](data-model.md).
Пять сущностей, связи, индексы, ограничения и миграция `InitialCatalog` созданы.

## Открытые решения

- Реальный Telegram ID первого администратора и настройки аутентификации для рабочего окружения; технический план доступа описан в F03.
- Название, оформление и демонстрационные товары.
- Публичный HTTPS-адрес и размещение.

## Что реализовано

- Сборка React и ASP.NET Core; локальный прокси `/api`.
- Стартовый экран с загрузкой, пустым состоянием и повтором при ошибке.
- Инициализация Telegram WebApp и переключение светлой/тёмной темы.
- Опциональный обработчик `/start` с кнопкой Mini App, выключенный по умолчанию.
- EF Core/Npgsql, пять сущностей и первая миграция PostgreSQL.
- Пять backend-проектов с отдельным Contracts и интерфейсами Application.
- Проверки работоспособности процесса, доступности PostgreSQL и применённых миграций.
- Интеграционные тесты ограничений и миграции на настоящем PostgreSQL.
- Compose, Dockerfile, совместная публикация и инструкция запуска.

Также реализованы каталог с фильтрами/страницами, карточка с вариантами,
проверка подписи Telegram и роли из БД, административные справочники и товары,
транзакционное сохранение агрегата и проверка версии xmin.
Локальная приёмка использует отдельный кластер, случайный тестовый токен и
явно созданного тестового администратора. Рабочая база не заполняется автоматически,
обход авторизации в приложение не добавлен. Фиктивные остатки отсутствуют.
