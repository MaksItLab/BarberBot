# Совместная работа: Максим, Codex и Claude

Над проектом работают владелец (Максим) и два AI-агента: Codex и Claude Code.
Агенты не общаются напрямую, поэтому координация идёт через репозиторий.

## Общие правила

- Единый источник правил — [AGENTS.md](../AGENTS.md). Codex читает его сам,
  Claude Code подключает через [CLAUDE.md](../CLAUDE.md). Отдельных правил
  для одного из агентов не заводим.
- Решения — в [decisions.md](decisions.md), задачи и приоритеты — в
  [backlog.md](backlog.md), порядок этапов — в [workflow.md](workflow.md).

## Как взять задачу

1. Перед началом проверить таблицу «Кто взял задачу» в [backlog.md](backlog.md)
   и открытые PR. Задачу, которую уже взял другой участник, не начинать.
2. Добавить строку в таблицу: ID задачи, исполнитель (`Максим`, `Codex` или
   `Claude`), ветку и статус. Эту правку включить в первый коммит ветки.
3. Если задача оказалась больше ожидаемого или зависит от чужой, написать
   об этом в описании PR, а не расширять задачу молча.

## Ветки и PR

- Одна задача — одна ветка и один PR. Прямые коммиты в `main` запрещены.
- Имена веток: `codex/<id>-<кратко>` и `claude/<id>-<кратко>`
  (допустимы служебные имена, которые назначает среда агента).
- В описании PR: задача из backlog, что сделано, какие проверки запущены
  и с каким результатом, что не проверено (например, настоящий Telegram).
- Перед PR подтянуть свежий `main` и разрешить конфликты в своей ветке.

## Перекрёстное ревью

- PR от Claude ревьюит Codex, PR от Codex ревьюит Claude. Замечания
  оставляются в PR с местом, проблемой, последствием и предлагаемым исправлением,
  как описано в [workflow.md](workflow.md#что-проверяет-ревьюер).
- Ревью другого агента — независимый проход, но не замена ревью владельца.
  Самопроверку автора по-прежнему не выдавать за независимое ревью.
- Автор исправляет замечания в той же ветке или отвечает в PR, почему не исправляет.

## Кто делает merge

С 23.10.2026 Максим разрешил агенту-исполнителю самому мержить свои PR, чтобы
не отвлекаться на каждый. Условия:

- каждый значимый сценарий покрыт тестами, и все тесты проходят на ветке,
  подтянутой к свежему `main`; известные нестабильные тесты указываются в PR;
- если тест упал, исправляется причина: код, если ошибка в коде, или тест,
  если неверен тест. Ослаблять или отключать тест ради зелёного прогона нельзя;
- нет конфликтов; цепочки PR мержатся по порядку, каждый — в `main`;
- PR, которые Максим отложил (сейчас R08, PR #1 — хостинг), не мержатся;
- самопроверка в PR не выдаётся за независимое ревью. Ревью другого агента
  желательно, но не блокирует merge.

Агенты не пушат в `main` напрямую и не одобряют PR от имени Максима. Максим
может в любой момент вернуть merge себе. После merge исполнитель обновляет
статус задачи в backlog.
