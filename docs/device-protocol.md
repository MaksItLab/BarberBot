# Протокол проверки на настоящих устройствах (R02, R10)

Автоматический набор (`node scripts/test-all.cjs`, CI) имитирует Telegram и сеть.
Здесь записываются только проверки в настоящем Telegram. Эмуляцию сюда не вносить.

Перед проверкой: закрыть старый Mini App, отправить боту `/start`, открыть новую кнопку.
При отказе записать «Код обращения» из сообщения: по нему запрос находится в журнале
(см. [diagnostics.md](diagnostics.md)).

## Сценарии

1. Вход: появляется «Управление магазином».
2. Создание товара с двумя вариантами → «Товар сохранён» → товар виден в каталоге.
3. Редактирование цены → повторное открытие показывает новую цену.
4. Свернуть Telegram на 1–2 минуты во время редактирования → вернуться: форма на месте.
5. Закрыть Mini App с несохранёнными изменениями → Telegram спрашивает подтверждение;
   открыть снова → предложение восстановить черновик.
6. Включить авиарежим во время сохранения → выключить → форма уточняет результат,
   дубль не появляется.
7. Сменить сеть (Wi-Fi ↔ мобильная, VPN вкл/выкл) и повторить 1–3.
8. Экранный диктор (TalkBack на Android, VoiceOver на iPhone), U06: пройти каталог →
   фильтр → «Показать ещё» (слышно «Показано N товаров») → товар → «Назад» (фокус на
   той же карточке) → управление → сохранение (слышно итог). Отметить, что не озвучено.
9. Крупный текст в настройках телефона (максимум): каталог, товар и форма без
   горизонтальной прокрутки, ничего не обрезано.
10. Экранная клавиатура, U04: в форме товара по очереди коснуться полей внизу экрана
    (цена варианта, описание) → поле видно над клавиатурой, при вводе не прыгает;
    закрыть клавиатуру → страница не скачет; «Сохранить товар» достижима прокруткой;
    после ошибки сохранения сообщение у поля видно. Развернуть Mini App на весь экран:
    ничего не уходит под вырез и кнопки Telegram. Записать версию Telegram и ОС.
