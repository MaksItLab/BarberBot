# T01. Разделение backend и Contracts

## PM + разработчик

Техническая задача выполняется перед F01. Результат — пять проектов backend
в одном solution и одном запускаемом ASP.NET Core приложении. Текущие HTTP-ответы,
структура таблиц и идентификатор миграции сохраняются.

## Аналитик

- Contracts содержит публичные запросы/ответы API и общие транспортные типы.
- EF-сущности, параметры подключения, TelegramOptions и внутренние модели
  сценариев не переносятся в Contracts.
- Domain и Contracts самостоятельны; Contracts не зависит от Domain.
- Application зависит от Domain и Contracts, описывает сценарии и интерфейсы.
- Infrastructure зависит от Application и Domain, реализует PostgreSQL и Telegram.
- Api зависит от Application, Infrastructure и Contracts. Infrastructure подключается
  в точке сборки приложения; HTTP-обработчики не используют DbContext напрямую.
- React получает JSON. C#-проект Contracts не является напрямую подключаемой
  библиотекой TypeScript; генерация клиентских типов может появиться с API каталога.

## Разработчик: технический план

1. Создать библиотеки Domain, Application, Infrastructure и Contracts.
2. Перенести сущности, EF-конфигурации/миграцию и Telegram worker по слоям.
3. Сохранить ID `20261015081714_InitialCatalog`; обновить CLR-имена в snapshot
   при переносе пространств имён, не менять операции Up/Down или схему.
4. Вынести проверку готовности БД за интерфейс Application; реализация в Infrastructure.
5. Для существующих ответов app/health использовать DTO из Contracts.
6. Обновить ссылки solution, тестов, Dockerfile, lock-файлы и EF-команды.
7. Актуализировать анализ F01–F06: сценарии и DTO в Application/Contracts,
   запросы EF и транзакции в Infrastructure, маршруты в Api.

## Приёмка и проверки

- Сборка без предупреждений; совместная публикация пяти сборок.
- Контроль зависимостей слоёв и JSON-контрактов тестами.
- Прежние 14 проверок на настоящем PostgreSQL проходят.
- Нет неприменённых изменений модели; SQL первой миграции не меняется.
- HTTP-ответы app/live/ready и клиентские маршруты совместимы.
- Отдельный проход ревью, исправления замечаний и повторные затронутые проверки.
