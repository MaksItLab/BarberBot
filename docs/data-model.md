# Согласованная минимальная модель данных

## Принятые требования

- Один товар представлен одной карточкой в каталоге.
- Размер, объём и оттенок выбираются внутри подробной карточки.
- У товара один бренд и один тип косметики.
- Все цены в рублях; учёт остатков в текущем MVP отсутствует.

## Сущности

| Сущность | Что хранит |
| --- | --- |
| Бренд | Идентификатор, название, необязательное описание бренда. |
| Тип косметики | Идентификатор, название: крем, сыворотка, шампунь и т. п. |
| Товар | Идентификатор, название, описание, бренд, тип косметики, необязательное изображение, видимость, даты создания и изменения. |
| Вариант товара | Идентификатор, товар, необязательные объём/вес, размер и оттенок, цена в рублях, видимость. |
| Пользователь | Идентификатор, уникальный Telegram ID, роль клиента или администратора, дата создания. |

Товар связан с одним брендом и одним типом косметики. Вариант принадлежит
ровно одному товару. У черновика товара может пока не быть вариантов;
для клиентского каталога требуется хотя бы один видимый вариант.
Роль хранится значением пользователя, без отдельных таблиц разрешений.

## Варианты и цены

Пример: одна карточка «Крем для лица», внутри варианты «50 мл — 900 ₽»
и «100 мл — 1 500 ₽». Это демонстрационные значения для объяснения модели.

- Каждая доступная комбинация объёма, размера и оттенка — отдельный вариант.
- Например, «30 мл, оттенок 02» и «50 мл, оттенок 02» могут иметь разные цены.
- Для MVP объём/вес, размер и оттенок хранятся как простые
  текстовые поля варианта. Отдельный универсальный конструктор характеристик
  в текущую версию не входит.
- Если у товара нет выбора, у него всё равно один вариант с ценой;
  интерфейс не показывает лишний переключатель.
- Цена хранится у варианта. Отдельную дублирующую цену у товара не храним.
- В каталоге показывается единственная цена либо «от … ₽», если цены
  видимых вариантов различаются. После выбора варианта показывается точная цена.
- Денежные суммы сохраняются с точностью до копеек, без вычислений через float/double.

## Видимость и остатки

Видимость — решение администратора о публикации. Она не означает наличие
товара на складе. В MVP не будет поля количества, надписей «Осталось N шт.»,
«В наличии», «Нет в наличии» и истории складских изменений.

Администратор может скрыть весь товар или отдельный вариант. Для показа
товара в клиентском каталоге нужен хотя бы один видимый вариант с ценой.

## Реализация базы

- Таблицы: `brands`, `cosmetic_types`, `products`, `product_variants`, `users`.
- Идентификаторы — `bigint` с генерацией в PostgreSQL; Telegram ID — отдельный уникальный `bigint`.
- Цена варианта — `numeric(12,2)` в PostgreSQL и `decimal` в C#, в рублях.
- Названия брендов и типов уникальны при точном совпадении.
- Комбинация товара, объёма, размера и оттенка уникальна, включая пустые
  характеристики (`NULLS NOT DISTINCT`). Отсутствие характеристики хранится
  как `null`, а не пустая строка.
- Отрицательные цены, пустые названия и некорректные роли запрещены ограничениями базы.
- Бренд или тип, на который ссылаются товары, нельзя удалить.
- При техническом удалении товара его варианты удаляются вместе с ним;
  в будущей админке основное действие — скрытие.
- Индексы поддерживают фильтрацию по бренду, типу и их сочетанию, а также
  поиск вариантов по товару и пользователей по Telegram ID.
- Продукт создаётся скрытым; варианты по умолчанию видимы.
- Даты хранятся в UTC. При сохранении изменений товара через `ShopDbContext`
  обновляется `UpdatedAt`, исходная дата создания сохраняется.
- Первая миграция — `InitialCatalog`. Автоматического изменения схемы при запуске нет.
- Версия товара отображается на системный `xmin` PostgreSQL через uint/IsRowVersion.
  Все административные изменения вариантов также обновляют родительский товар.
  Публичный API не раскрывает xmin, админский передаёт непрозрачную строку версии.
  `ProductConcurrency` фиксирует это отображение в модели EF, без нового столбца.

## Прикладные операции

Каталог отбирает видимые товары с видимыми вариантами. API и формы админки
проверяют ввод/публикацию и сохраняют товар с вариантами одной транзакцией.
Окончательное удаление через административный API не предоставляется.
